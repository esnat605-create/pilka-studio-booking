# Pilka Studio — страница онлайн-записи

Публичная страница, на которой клиент салона сам выбирает услугу, мастера и
свободное время. Запись попадает в ту же базу, с которой работает админка
Pilka Studio, и сразу видна администраторам.

- **Фронтенд** — обычные HTML/CSS/JS без фреймворков и сборщика, mobile-first.
- **Бэкенд** — три бессерверные функции Netlify на Node.js.
- **База** — тот же проект Supabase (PostgreSQL), что и у админки. Новых баз не заводим.

---

## 1. Как это устроено

```
Браузер клиента
      │  fetch /api/catalog, /api/slots, /api/book
      ▼
Netlify Functions  ──── DATABASE_URL ────►  Supabase (та же база, что у админки)
      │
      └── пишет: appointments (статус «Не подтверждён») + web_bookings (журнал)
```

Браузер никогда не обращается к Supabase напрямую — ключи Supabase в код
страницы вообще не попадают, вся работа с базой идёт на сервере.

Запись создаётся сразу в существующей таблице `appointments` со статусом
**«Не подтверждён»**, с `source = 'Сайт'`. Слот занимается сразу, поэтому одно
и то же время невозможно продать дважды — с сайта и из админки. Каждая заявка
дополнительно пишется в таблицу `web_bookings` — журнал обращений с сайта.

Схема базы уже применена вместе с админ-панелью (`web_bookings`, `master_days_off`,
`masters.photo_url`, настройки `siteStepMinutes` и `categoryOrder`) — отдельно
накатывать здесь нечего.

---

## 2. Что нужно сделать один раз

### Шаг 1. Переменная окружения DATABASE_URL

Site configuration → Environment variables → задать `DATABASE_URL` — та же
строка подключения (Transaction pooler, порт 6543), что и у админки. Пример —
в `.env.example`.

### Шаг 2. Наполнить каталог через админку

Сайт ничего не показывает, пока в базе нет мастеров и услуг:

1. В админке откройте вкладку **«Мастера»** — добавьте мастеров, у активных
   поставьте фото (необязательно) и отметьте выходные дни.
2. Откройте вкладку **«Услуги»** — добавьте услуги с ценой и длительностью.
3. В **«Настройках»** укажите название салона, часы работы и, при желании,
   порядок категорий услуг для сайта (`categoryOrder`) и шаг сетки времени
   (`siteStepMinutes`, по умолчанию 30 минут).

Сайт подхватывает изменения сразу — обновлять ничего не нужно.

## 3. Локальный запуск

```bash
npm install
DATABASE_URL=postgresql://... node dev_server.js
```

Открыть http://localhost:8877

## 4. Структура проекта

```
public/            — статический фронтенд (раздаётся как есть)
  index.html
  style.css
  script.js
  assets/
netlify/functions/  — серверные функции
  catalog.js         GET  /api/catalog — услуги, мастера, часы работы
  slots.js           GET  /api/slots  — свободное время у мастера на дату
  book.js            POST /api/book   — создание записи
  lib/core.js         общая логика: база, время, антиспам, расчёт слотов
netlify.toml        — редиректы /api/* → функции, заголовки безопасности
```

## 5. Антиспам и защита от накладок

| Ситуация | Поведение |
|---|---|
| Двое выбрали одно время одновременно | Транзакция с блокировкой по паре (мастер, дата) — второй получит «это время только что заняли». |
| Клиент подделал запрос и шлёт занятое время | Сервер заново считает свободные слоты и отклоняет. |
| Клиент подставил свою цену или длительность | Игнорируются — берутся из таблицы `services`. |
| Отменённая запись или неявка | Время освобождается — как и в админке. |
| У мастера не настроены услуги | Показываются все услуги. |
| Мастер отключён (`active = false`) | На сайте его нет. |
| Боты | Скрытое поле-ловушка, отсечка по времени заполнения, лимит по номеру телефона. |
